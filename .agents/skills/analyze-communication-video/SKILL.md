# Analyze communication video

Work in this project. Read `AGENTS.md`, `README.md`, `context/profile.md`, `context/rubric-v1.md`, `context/personal-style/goal-v1.md`, `context/personal-style/rubric-v1.md`, `measurement/progress-v1.md`, `workflows/evaluate-session.md`, `memory/approved-calibration.md`, both files in `verifiers/` named `evidence-reviewer.md` and `personal-style-reviewer.md`, and `measurement/session-record-v1.md`. Treat project rubric and the personal rubric as custom estimates. The personal rubric is a draft. Never present either as certified proficiency or combine them into a single score.

1. Use the provided media (local path, attachment, or authorized URL), or ask for the recording when missing. Identify the target speaker, goal/audience, topic, and first take versus rehearsal from user-provided context. Do not block on optional missing context; mark it unknown and disable unsupported criteria. Do not invent pre-speech confidence, intended point, listener reaction, or data absent from the recording. Do not send personal audio, video, transcripts, reports, or notes outside the device without explicit authorization; preserve originals. If using a URL, do not fetch private media through a third party without authorization.
2. Create a unique directory `private/sessions/<date>-<unique-id>/` without overwriting existing files. Save a manifest with media source, SHA-256 if locally available, session ID/date, input modalities and observed technical limitations. Analyze the media with the session's native video/audio capability (for example Antigravity video analysis or Gemini) when the user has authorized that environment. Use direct viewing/listening as the primary evidence; if the environment also provides a transcript, keep raw and reviewed transcripts separate. Do not require or install a local speech model. If the environment cannot access the media, say so, ask for an authorized video-capable environment or a transcript, and do not claim to have seen or heard it. Unreviewed transcription alone does not support pronunciation, intelligibility or vocal delivery. Video observations need actual viewable footage.
3. Follow `workflows/evaluate-session.md`. For each applicable general and personal criterion, locate timestamped, modality-specific evidence and propose the closest anchor. Identify both strengths and opportunities. Mark missing evidence `not_assessed` or `not_applicable`; no inferred emotion, internal confidence or listener response. Relevant grammar or vocabulary corrections must be grounded in audio-reviewed speech and preserve intended meaning. A transcript match only proves a text match.
4. Check the draft against both verifier instructions before the report: timestamps in range, transcript reference exact, evidence relevant, source and modality sufficient, no invented corrections. If a genuinely separate reviewer with appropriate authorized access is available and delegation is allowed, ask them to perform the independent review; record who and their findings. Otherwise perform the checks you can and mark `not independently reviewed`; never simulate a separate agent, listening, verification or success. Keep contradictory/uncertain findings visible.
5. Write a private report based on `templates/report.md`: a short overview, supported strengths, applicable criterion ratings and evidence, one priority with an actionable drill, uncertainty, verifier status, and any self-reports. Include **3–5 suggested words or phrases** genuinely relevant to the actual topic and audience when enough context exists: plain meaning, a short natural example grounded in the topic, and why useful. These are optional suggestions, not asserted mistakes. Cite the user's timestamp only when the original speech actually motivates it; never invent a misused word or penalize a reasonable alternative. If topic is unknown, say so and omit the list.
6. If scores can be supported, save `scores.json` conforming to `measurement/session-record-v1.md`; keep every criterion, reviewer status and evidence. Values from missing observations remain null. If no scores can be supported, save a report with `not_assessed` and do not fabricate a score record. Never modify old sessions or rubric versions. After completion append an accurate entry to `private/process.md`; identify repeat inputs by hash and do not count duplicate analyses as new takes. Use `python3 scripts/progress.py` for comparable first-take history only after a real score record exists; report sparse samples and exclusions. Explain to the user what was actually reviewed and link to the private report.
